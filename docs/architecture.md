# ComicWise Architecture

This document provides a high-level overview of the ComicWise (comicr) project
architecture, including system components, data flow, and design rationale.

## 1. System Overview

ComicWise is structured with a strict 3-layer pattern:

- **Schema Layer**: Zod schemas for input validation (src/schemas/)
- **Database Layer**: Drizzle ORM queries/mutations (src/database/queries/,
  src/database/mutations/)
- **Action Layer**: Server actions (src/actions/) with "use server" directive

## 2. Data Flow

UI Component → Server Action (Zod validation, auth check) → DAL/Mutation/Query →
Drizzle → PostgreSQL

## 3. Component Interactions

- All mutations/queries go through DAL (e.g., userDAL.getById())
- API responses follow `{ success, data?, error?, message? }` shape
- Flat-to-tree comment threading via `buildCommentTree`

## 4. Security & RBAC

- Roles: user, moderator, admin
- Sensitive actions logged to audit table
- Soft delete for users/comments (set deletedAt, anonymize PII)

## 5. Performance

- Redis for hot data caching
- Indexed FKs/search fields
- WebP/AVIF for images, lazy load in UI

## 6. Storage & Caching

- Multi-provider storage (S3, ImageKit, Cloudinary, local)
- Redis cache abstraction in `lib/cache/`

## 7. Testing & Validation

- Unit tests: schemas, utilities, RBAC, DAL, actions
- E2E tests: reader, profile, rating, comments, admin panel
- Validation: `pnpm validate` runs type-check, lint, and all tests

## 8. Audit Logging

- All sensitive actions logged to DB and file
- Audit log schema detailed in docs/rbac.md

## 9. Error Handling

- Success: `{ success: true, data }`
- Error: `{ success: false, error: string }` or
  `{ success: false, error: { code, message } }`
- Paginated:
  `{ success: true, data: [...], meta: { page, limit, total, totalPages, hasNextPage, hasPrevPage } }`
